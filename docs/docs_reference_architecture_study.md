# 参考架构研究与独立实现边界

**研究日期：** 2026-08-26  
**适用版本：** Vellum 后续重构

## 研究范围

本次仅在隔离目录中审阅了公开仓库的目录、模块命名、构建分层与许可文本：GNOME Text Editor（`GNOME/gnome-text-editor`）和 mini-text（`Nokse22/mini-text`）。两者的 `COPYING` 均声明 GNU GPL；因此，**Vellum 不复制、改写、移植或派生其中的 C、Python、UI XML、CSS、图标、翻译、资源文件或测试代码**。参考对象仅提供产品层面的交互观察与通用架构原则。

## 可借鉴的非表达性原则

| 观察对象 | 可借鉴的通用原则 | Vellum 的原创落实方式 |
| --- | --- | --- |
| GNOME Text Editor | 将应用、窗口、文档、视图、状态栏、设置与文件监测拆为职责单一的模块，而不是将所有生命周期和界面行为堆叠于窗口实现 | 在现有 `MtApplication`、`MtWindow`、`MtDocument`、`MtSettings` 与 `MtPluginManager` 之间补全明确的模式策略和测试接口；不采用其名称、函数、UI 文件或实现 |
| GNOME Text Editor | 核心编辑循环与可选能力保持边界，使窗口可在低复杂度状态下维持稳定的文档、保存与标签页体验 | Vellum 的“无扩展”启动路径只保留文档标签、编辑、打开/保存、查找、撤销、语言识别和主题/字体等核心功能；项目、AI、构建、Vi 等进入扩展层 |
| mini-text | 极简场景以单个主编辑区为视觉中心，避免在无额外任务时固定展示侧栏、工具面板与大量动作 | Vellum 将按加载的扩展决定是否显示辅助区域；无扩展时不保留空白面板、项目侧栏或构建输出区 |
| 两者 | 以 Meson、资源、翻译和数据安装规则分层，而不是将运行时资产散落到业务代码中 | 保持现有 Meson / `data` / `po` 结构，并为 TUI 测试单独设置测试目标和可控协议，不混入图形应用运行路径 |

## 明确排除的内容

Vellum 仍是独立 BSD-2-Clause 项目。下列内容不属于此次学习的可复用范围：具体窗口树、控件顺序、文字、快捷键列表、源代码、函数名、类型名、图标、CSS 规则、GResource 内容、翻译、测试及任何可识别的视觉资产。后续代码会保留 Vellum 的 `Mt*` 命名、中文注释和 BSD Allman 风格，并以原创测试证实行为。

## 重构导向

后续重构应围绕以下可验证目标进行：第一，无已启用扩展时，窗口只呈现标题栏、标签页和编辑器等最小核心；第二，扩展激活后才能请求附属面板、独立窗口或覆盖层；第三，所有扩展相关显示路径在窗口销毁、文档关闭、切换标签页时均可被安全取消；第四，TUI 调试器以有限、可审计的命令查询状态和触发动作，而非模拟任意 GTK 内部调用。

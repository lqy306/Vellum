# Vellum TUI 调试器

`vellum-tui-debug` 是 Vellum 的**受限调试入口**。它仍会创建真实的 GTK4/Libadwaita 窗口，但通过标准输入接收小型文本协议，并在标准输出以一行一个 JSON 对象返回当前界面可观察状态。它用于自动化回归、无桌面会话排错和保存/编辑流程验证，不是终端版文本编辑器，也不允许执行任意 GTK 调用或 shell 命令。

默认情况下，调试器会创建临时 XDG 配置目录、显式关闭扩展加载并创建一个未命名文档。因此，它不会读取或修改正常用户的 Vellum 偏好、动态扩展或 AI 配置。若显式设置 `VELLUM_TUI_CONFIG_HOME`，则该目录由调用者负责隔离和清理。

| 命令 | 参数与语义 | 输出 |
| --- | --- | --- |
| `HELP` | 返回允许命令清单。 | `{"ok":true,"event":"help",...}` |
| `STATE` | 返回文档数量、标题、原始源文本、修改/保存状态以及两个扩展面板是否可见。 | 一个完整状态 JSON 对象。 |
| `NEW` | 创建并选中新文档。 | 成功事件。 |
| `TEXT <C 转义文本>` | 用文本替换当前文档；`\n` 表示换行，`\t` 表示真实 Tab。 | 成功或失败事件。 |
| `INSERT <C 转义文本>` | 在当前光标位置插入文本。 | 成功或失败事件。 |
| `OPEN <绝对路径>` | 异步打开绝对路径文件。 | 已请求打开事件；随后用 `WAIT` 和 `STATE` 检查完成状态。 |
| `SAVE <绝对路径>` | 将当前文档保存到绝对路径。 | 已请求保存事件；随后用 `WAIT` 和 `STATE` 检查完成状态。 |
| `ACTION <名称>` | 仅允许 `new`、`find`、`replace`、`zoom-in`、`zoom-out`、`zoom-reset`、`force-close`。 | 成功或允许列表拒绝事件。 |
| `WAIT <0–5000>` | 驱动 GLib 主循环指定毫秒数，供异步加载或保存完成。 | 成功或参数错误事件。 |
| `QUIT` | 返回退出事件并安全销毁 GTK 窗口。 | 成功事件，随后退出。 |

在有 X11/Wayland 图形会话时可以直接运行。在 CI、云主机或纯终端环境中，可用虚拟显示运行：

```sh
printf '%s\n' \
  'TEXT # Heading\\n- item' \
  'SAVE /tmp/vellum-demo.md' \
  'WAIT 1000' \
  'STATE' \
  'QUIT' | xvfb-run -a ./build/src/vellum-tui-debug
```

内置回归 `tui-debug` 使用该协议确认：会话不加载扩展，包含换行的文本可写入真实文档，异步保存完成后目标文件内容正确。

> 此接口刻意不包含任意路径删除、任意动作激活、插件加载、网络请求、命令执行或设置写入。它的目标是让 GUI 行为可观察、可重复测试，而不是扩大应用攻击面。
